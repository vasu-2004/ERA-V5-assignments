India, in four languages.
Measured, not guessed.

Real corpus statistics and a real, from-scratch, standard byte-level BPE tokenizer trained on the "India" Wikipedia article in English, Hindi, Telugu, and Marathi — every number on this page comes straight out of scripts/run_analysis.py, no hand-editing. This is the baseline (equal-weight, undifferentiated) run that the final, tuned, 10,000-token tokenizer will be built on top of.

Note on scope: this is the baseline research phase — a single, plain BPE trained with no per-language tuning. As the fertility table below shows, this naive approach does not reach the assignment's X ≤ 1.2 target for any language yet. The next phase allocates the 10,000-token budget unevenly across languages to close that gap and minimize the score-relevant spread — not attempted here.
1–4

Per-language corpus statistics

Source files copied byte-for-byte into data/, exactly as supplied — no content cleaning applied (page navigation/reference chrome is included, since that's what was in the source files). Only standard universal-newline normalization (\r\n → \n) happens on read.

Total characters = every Unicode code point in the file. Total running words = whitespace-split token count (independently cross-checked against wc -w under a correct UTF-8 locale — this environment defaults to POSIX/C, under which wc -w silently miscounts multi-byte UTF-8 text, so that cross-check needed an explicit LC_ALL=C.UTF-8). Unique words shown both raw (as-is) and punctuation-stripped (trailing/leading Unicode punctuation removed per token). Distinct Unicode characters = size of the actual character alphabet used (full lists in artifacts/distinct_unicode_chars.json).

5

Baseline BPE fertility vs. merge count

One byte-level BPE tokenizer trained on the combined corpus (all four languages' word-frequency counts summed directly — equal weights, no per-language boost). Base alphabet = 256 raw UTF-8 bytes, then 10,000 greedy frequency-ranked merges. Fertility = average tokens per unique (punctuation- stripped) word for that language, at each checkpoint. Trainer verified against the textbook low/lower/newest/widest BPE example before running on real data.

Takeaway. A flat, undifferentiated 10,000-merge budget gets every language only to ~2.2–2.7 tokens/word — nowhere near the ≤1.2 target. Telugu is consistently hardest to compress (complex conjunct orthography, smallest corpus); Hindi consistently compresses best despite a smaller corpus than English. Closing the gap to ≤1.2 — and tightening the spread the assignment actually scores on — needs a deliberately unequal per-language allocation, planned next.
