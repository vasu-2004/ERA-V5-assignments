Bharat-40B: an India-first plan

A 40B model that reasons from an Indian frame and is genuinely strong at coding, agentic work, and Indian-language use. This is the data, evaluation and tokenizer plan — every number is an estimate, stated with the reasoning that produced it.

Thesis. "India-first" is not "English model + Indic translations." It means Indian context, knowledge and values are the default frame: Indian English & code-mixing are first-class, the token budget is spent so Indic scripts are cheap, and both the training data and the private evals are built around Indian domains (law, UPI/finance, agriculture, health, governance, JEE/NEET/UPSC). Coding + agentic strength comes from verifiable-reward RL, not scale alone.

1Model shape & targets

40B MoE (~8B active) over a dense 40B: India needs cheap inference on modest/edge infra, and sparse activation buys quality-per-FLOP. Target quality is Gemma-4-class as a reference for data ambition, not an eval target. We over-train (~200 tok/param, ~8T) because the model is inference-bound in deployment — spend train compute to shrink serving cost.

The scarcity reality (the hard part). Genuinely high-quality Indic text is ~2 orders of magnitude smaller than English — perhaps a few hundred B real tokens across all 12. We hit 1.8T honestly by: (a) upsampling the cleanest Indic 2–4× (watch memorization); (b) synthetic augmentation — translate high-quality English reasoning/code into Indic with a strong MT model + quality-filter, generate India-context Q&A, add Indic code comments; (c) ASR-mining spoken Indian content into text; (d) cross-lingual transfer from the English/code backbone. We do not pad with low-quality scraped Indic web — that would poison fluency.

  • Tool-use / function-calling / multi-step agents
  • India tasks: law & rights, UPI/finance, agriculture advisory, public health, govt-scheme navigation, JEE/NEET/UPSC
  • Code-mixing (Hinglish/Tanglish) and long-context

RL / alignment

  • RLVR (verifiable rewards) — the coding/agentic engine: unit-tests for code, checkers for math, task-success in sandboxes for agents
  • DPO/GRPO on preference data from Indian annotators
  • Constitution encoding Indian pluralism & values; non-Western-default framing
  • Safety for Indian context: communal harmony, elections, medical/legal caution, misinformation

7Fertility targets → tokenizer size

Fertility = tokens per word. An English-centric tokenizer (Llama-class) spends 3–6 tokens/word on Indic scripts — Indic users pay 3–5× the cost and lose effective context. India-first means buying that back with vocab. Targets below are for a script-balanced 256k tokenizer with byte fallback and digit splitting:

Language / domainTarget tok/wordNaïve (Llama-ish)Note
English1.15–1.25~1.3Near-optimal already
Hindi / Marathi (Devanagari)1.4–1.63–4Shared Devanagari subwords
Bengali / Gujarati / Punjabi / Odia1.5–1.84–5Own scripts, moderate morphology
Telugu / Tamil / Kannada / Malayalam1.9–2.25–6Agglutinative + complex conjuncts → higher per-word, but words carry more; ~parity per character
Urdu1.5–1.84–5Perso-Arabic
Code~1.3~1.4Indent/identifier-aware
Math1.2–1.52–3Digit-splitting, symbol tokens
Agentic (JSON/tool)efficient—Structured-syntax tokens
Why 256k (not 32k, not 512k). To hit ≤~2 tok/word across four script families + English + code + math simultaneously, you need slots per script. Rough allocation: ~70k English/code/math, ~20k digits/symbols/JSON/special + byte fallback, ~165k Indic (shared across scripts where possible). Cost: at hidden≈5k the embedding+softmax is ~1.3B params tied — ~3% of 40B. Benefit: for an India-first workload, Indic sequences shrink ~2.5–3×, directly cutting inference cost and extending usable context. At 40B the embedding overhead is cheap; the per-token savings on the actual traffic are not. 32k would betray Indic users; ≥512k wastes params on rare tokens and slows softmax. 256k is the India-first sweet spot — and, not coincidentally, where strong multilingual tokenizers (Gemma-class) already sit.

Tokenizer training data is rebalanced (low-resource Indic upsampled) so their fertility isn't sacrificed to English frequency; byte-fallback guarantees zero UNK; numbers are split to digits for math.

8The headline numbers, in one breath

A 40B MoE (~8B active) over-trained on ~8T tokens — 30% English, 22% code, 22% Indic (12 languages, honestly reached via upsampling + verified synthetic), 10% math/science, 6% agentic, 5% India-knowledge, 5% parallel — cleaned on cloud with dedup/quality/decontamination and Indic-specific normalization; aligned with RLVR for coding/agentic and Indian-annotator preferences for values; measured on private India-first benchmarks; and served through a 256k script-balanced tokenizer that keeps Indic fertility ≤~2 tokens/word so the model is cheap where India actually uses it.
